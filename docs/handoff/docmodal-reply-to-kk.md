# 회신 — `DocModal` (kk `dsl-docmodal.md` 요청건)

작성 2026-08-12 · 부품 쪽(erp-dsl). **아직 커밋·발행 전이고, 발행 시 `0.85.0`**(신규 부품 + 이름 변경, 별칭 있음).

---

## 0. 결론 한 줄

**요청 일곱 중 여섯은 그대로, 하나(`@page` 여백)는 값이 뒤집혔습니다.** 그리고 진단은 맞습니다 —
인쇄 경로는 「무엇으로 그렸나」에 안 묶여 있고, 클래스 계약 하나(`.erpPaperSheet`)에 걸려 있습니다.

## 1. 새 API

```tsx
import { DocModal, PaperSheet } from '@jjaim519/erp-dsl';

// ① 서식 문서 — 지금 그대로(회귀 0)
<DocModal opened onClose={…} title="견적서" spec={spec} values={values} />

// ② 손코딩 문서 — 각 장을 시트로
<DocModal opened onClose={…} title="계약서" orientation="portrait"
          actions={[{ label: '승인 요청', variant: 'primary', onClick: req }]}>
  <PaperSheet><ContractPage1 /></PaperSheet>
  <PaperSheet><ContractPage2 /></PaperSheet>
</DocModal>
```

- `spec`과 `children`은 **택일**입니다(타입이 막습니다). `children`이면 `orientation`이 필수입니다.
- `PaperDocModal`은 **별칭으로 한 릴리스** 남습니다(`@deprecated`). 다음 minor에서 사라집니다.
- **`PaperSheet`가 안쪽 여백 15mm를 갖습니다**(서식 문서의 격자 여백과 **같은 상수**). 옮기실 때
  기존 문서가 자기 `padding: 48px` 같은 걸 들고 있으면 **빼 주세요** — 두 겹이 됩니다.
  회사 서류의 여백이 한 값이 되는 게 이 통일의 목적 중 하나입니다.

### 크롬(§3 오너 지시 반영)

| | |
|---|---|
| 배율 토글 | **삭제 · 100% 고정.** 실측(ResizeObserver)·프레임 계산도 같이 사라졌습니다(그건 「맞춤」 전용 계산기였습니다) |
| 그 자리 | **`toolbar?: ReactNode`** — 열린 슬롯입니다. `views: {label,value}[]`로 **안 닫았습니다**: 어떤 도메인은 토글이 아니라 라디오·선택입니다(오너 지시) |
| 인쇄 | **헤더로** (푸터는 «이 문서로 무슨 일을 하나»의 자리) |
| 좌하단 닫기 | **삭제**(✕와 중복). 편집의 `취소`는 남되 **`withCancel`로 소비처가 끕니다**(기본 켜짐 — 그건 닫기가 아니라 `저장`의 짝입니다) |
| 우하단 | `actions` CTA 한 자리. **없으면 푸터를 통째로 안 그립니다**(빈 띠가 안 남게) |

⚠ 100% 고정의 대가: **창이 종이보다 좁으면 데스크가 가로로 스크롤됩니다**(가로 문서 1123px).
그게 「배율은 인쇄 미리보기에서 본다」의 뜻입니다.

## 2. §2-5 만 값이 뒤집혔습니다 — `@page { margin: 0 }`

소유권 이관은 그대로 받았습니다(**이제 껍데기가 두 모드 모두에 `@page`를 깝니다** — 앱의
`@media print` 블록 6곳은 걷어내십시오). 다만 **여백은 0이어야 합니다.**

- 시트는 물리 210mm로 못박혀 있습니다. `margin: 10mm`를 주면 인쇄 가능 폭이 190mm가 되어
  **모든 장이 두 장으로 흘러넘칩니다** — 계약서가 겪는 것과 반대 방향의 같은 사고입니다.
- 그리고 **머리글·바닥글을 없애는 게 바로 그 `margin: 0`입니다.** 가구 발주서에 머리글이 찍힌 건
  여백이 0이어서가 아니라 **그 라우트에 `@page` 규칙 자체가 없어서**입니다. 검증에서 그대로 보였습니다:
  규칙이 있는 인쇄물엔 URL·날짜·쪽번호가 없고, 없는 인쇄물엔 찍힙니다.

## 3. 검증 (수용 기준 대조)

부품이 만드는 DOM과 **실제 `paper.css`**로 픽스처를 세워 헤드리스 크롬으로 인쇄 PDF를 뽑았습니다.
(dev 서버는 오너가 관리하므로 안 띄웠습니다. React 배선은 `tsc` EXIT=0.)

- ✅ `children` 3장 → **정확히 3쪽**, A4 세로(595×842pt). 겹침·빈 장 없음, 각 장 바닥 표시가 제 쪽에 있음
- ✅ `landscape` 3장 → 3쪽, **842×595pt**(가로)
- ✅ 인쇄물에 모달 크롬(제목·버튼·오버레이·회색 데스크)이 **안 찍힘**
- ✅ 모달이 **닫혀 있을 때** 앱 화면 인쇄 → 정상 1쪽(백지 사고 재발 없음)
- ✅ 브라우저 머리글·바닥글 없음(`@page margin:0`)
- ⏳ **`spec` 모드 회귀 0** — 코드 경로는 안 건드렸습니다(주입 문자열을 `paperPrint.ts`로 **옮기기만** 했고
  값은 동일). 다만 「보고 확인」은 아직입니다 — **박물관 `/dev/part` → DocModal**에서 서식 문서 보기·편집·인쇄를
  한 번 봐 주십시오(데모에 손코딩 3장도 같이 박아 뒀습니다)
- ⏳ 긴 문서 스크롤 밖 인쇄 — 기존 `.erpDocDesk` 규칙 그대로라 회귀는 아니지만, 실문서로 한 번 보시면 좋습니다

## 3-1. ⚠ 진단 정정 — `PaperDocModal` 인쇄도 **원래 백지였습니다**

요청서 표에 `PaperDocModal` = (정상)으로 적혀 있는데, **오너가 실제로 눌러 보니 백지가 나왔습니다.**
저희 픽스처는 통과했는데 실물이 백지였고, 차이는 **DOM 한 겹**이었습니다.

Mantine 8은 모달을 `body` 직계에 안 붙입니다 — `<div data-mantine-shared-portal-node>`(팝오버·툴팁과
**공유**하는 상자)를 만들어 그 *안*에 넣습니다. 그런데 「문서 밖 감추기」는 이렇게 적혀 있었습니다:

```css
html.erp-doc-print body > *:not(.mantine-Modal-root) { display: none !important; }
```

공유 상자엔 저 클래스가 없으니 «문서 밖»으로 판정돼 **모달째 사라졌습니다.** `PaperModal` 쪽이
`visibility`를 쓰는 바람에 이 결함을 안 만난 것뿐이고, **`PaperDocModal`은 v0.84.0까지 이 상태입니다**
(견적서 갑·을 · 갑지 · 사용내역서 · 거래처 발주서 — 모달에서 인쇄하면 백지). 확인해 보십시오.

고친 방법: **우리 상자를 따로 받아 우리 이름을 겁니다**(`portalProps={{ reuseTargetNode: false,
className: 'erpDocPortal' }}`) → 선택자도 `.erpDocPortal`로 바뀝니다. 남의 클래스는 남의 사정으로
바뀌므로 계약을 거기 걸지 않습니다. 덤으로 공유 상자에 얹힌 남의 포털(툴팁 등)이 종이에 묻어
나오는 경로도 같이 막힙니다.

재현·검증(공유 상자 한 겹을 넣은 픽스처): **옛 선택자 → 1쪽 1KB(백지) / 새 선택자 → 3쪽 67KB.**

## 4. 폐기

`PaperModal`은 **폐기 예정**으로 표시했습니다(README·카탈로그·소스 주석). 삭제는 **다음 minor**입니다 —
그때 `controls.css`의 `.erpPaper` 인쇄 빌트인도 같이 걷어냅니다. 계약서·카탈로그 발주 요청서 이관 후
알려 주시면 그 시점을 잡겠습니다.

`MobilePaperViewer`는 이번 통일에 안 들어갑니다(동의).
