# 요청 — 화면 빈도 지도 (위젯 우선순위 실측)

> **이 문서를 소비처 레포에서 그대로 실행해 주세요.** 산출물은 아래 「답의 형식」의 표 다섯 개입니다.
> 레포가 여럿이면 **레포마다 한 부**를 만들고 맨 뒤에 합산표를 붙여 주세요.

---

## 0. 무엇을 묻고, 무엇을 묻지 않는가

**묻는 것:** *"어떤 «모양»의 화면과 «덩어리»가 몇 번 되풀이되는가."*
**묻지 않는 것:** *"어떤 부품을 만들어야 하는가."*

이 구분이 이 요청의 전부입니다. 부품 목록은 저희가 결정합니다. 여기서 필요한 건 **무엇부터 손댈지 정할 실측 근거**뿐입니다.

그래서 답을 쓸 때 두 가지를 지켜 주세요.

- **도메인 이름은 식별자로만.** 「발주 목록」은 위치를 가리키는 이름일 뿐이고, 분류는 **「목록형」**입니다. 도메인이 분류가 되면 그 순간 «발주위젯»이 생기고, 그건 저희가 만들지 않기로 한 것입니다.
- **우리 부품 이름으로 답하지 마세요.** "여긴 DataTable이 어울림" 같은 판단 말고, **지금 화면에 무엇이 있는지**를 적어 주세요. 매핑은 저희가 합니다.

**세는 단위는 «화면»입니다.** 같은 덩어리가 한 화면에 두 번 나와도 **1**로 셉니다(빈도는 «몇 화면에서 필요한가»지 «총 몇 개인가»가 아닙니다).

---

## 1. 답의 형식

### 표 A — 페이지 유형별 빈도

| 유형 | N | 대표 경로 3개 |
|---|---|---|
| 목록형 | | |
| 상세형 | | |
| 작성·편집형 | | |
| 대시보드형 | | |
| 2-pane 작업형 | | |
| 문서형 | | |
| 설정·관리형 | | |
| 기타(자유 기술) | | |

분류 기준은 **§2**에 있습니다. 어디에도 안 맞으면 «기타»에 넣고 한 줄로 설명해 주세요 — **그 «기타»가 제일 값진 데이터입니다.**

### 표 B — 페이지 «본문 블록» 빈도 ← 이게 핵심입니다

페이지 본문에 놓이는 덩어리 하나하나입니다. 각 행에:

| 블록 | N(화면 수) | 대략 폭 | 높이 성격 | 지금 무엇으로 | 대표 경로 |
|---|---|---|---|---|---|
| 예: 표(정렬·페이징 있음) | 14 | 전폭 | 내부 스크롤 | 자체 Table 컴포넌트 | /orders, /vendors, /items |

- **대략 폭** — 화면을 **12칸**으로 봤을 때: `12(전폭) / 9 / 8 / 6(절반) / 4 / 3`
- **높이 성격** — `고정` · `내용만큼 늘어남` · `내부 스크롤` 중 하나
- **지금 무엇으로** — 우리 패키지 부품명 / 자체 컴포넌트명 / `손으로(div+css)`

블록 어휘는 **§3**에 있습니다. 목록에 없는 게 나오면 **새 행을 만들어** 이름을 붙여 주세요.

### 표 C — 오버레이 안의 내용 (모달·드로어·시트)

표 B와 **같은 형식**이되 **오버레이 안에 있는 것**만 따로 세 주세요.
이유: 저희 규칙상 **페이지에 올라가는 것(위젯)과 위에 떠서 닫히는 것(오버레이)은 다른 층**이라, 섞이면 판정이 틀립니다.

### 표 D — 손으로 짠 반복 (승격 후보)

같은 걸 **여러 화면에서 손으로 다시 만든** 자리입니다.

| 무엇 | 몇 화면 | 왜 부품을 안 썼나(추정 가능하면) |
|---|---|---|
| 예: 상태 배지 + 날짜 한 줄 | 9 | 배지에 날짜를 붙이는 부품이 없어서 |

**«왜 안 썼나»가 표 D의 본체입니다.** 3번 이상 반복됐다면 그건 저희 부품에 구멍이 있다는 신호입니다.

### 표 E — 막힌 자리

부품이 없어서 **우회했거나 포기한** 자리. 코드 주석의 `TODO`/`HACK`/`임시`, 또는 기억나는 것.

| 하려던 것 | 어떻게 우회했나 | 경로 |
|---|---|---|

## 2. 페이지 유형 판별 기준

애매하면 **«이 화면에서 사용자가 하는 일»** 하나로 가르세요.

| 유형 | 판별 | 헷갈리는 짝 |
|---|---|---|
| **목록형** | 여러 건을 훑고 **하나를 고른다** | 대시보드형과 헷갈리면: 목록형은 «건»이 주인공, 대시보드형은 «수치»가 주인공 |
| **상세형** | **한 건**을 보고 그에 대해 행동한다 | 편집 폼이 있어도 «보는 게 주»면 상세형 |
| **작성·편집형** | **값을 만든다.** 화면 대부분이 입력칸 | 상세형과 헷갈리면: 저장 버튼이 화면의 목적이면 작성형 |
| **대시보드형** | 여러 지표를 **동시에** 본다. 클릭이 목적이 아님 | |
| **2-pane 작업형** | 좌에서 고르고 **우에서 작업**. 좌우가 계속 같이 보여야 함 | 목록형+상세형을 한 화면에 둔 것 |
| **문서형** | A4/장표 — 인쇄되거나 인쇄를 전제 | |
| **설정·관리형** | 항목이 나열되고 각각을 켜고 끄거나 값을 바꾼다 | |

## 3. 본문 블록 어휘 (표 B·C 공통)

없는 게 있으면 **새로 만들어 적어 주세요.**

**데이터를 보여주는 것**
`표(정렬·페이징)` · `표(편집 가능)` · `카드 격자` · `KPI 타일 줄` · `차트` · `트리·계층` · `달력·일정` · `타임라인·이력`

**값을 만드는 것**
`폼 섹션` · `가변 항목 목록(추가/삭제)` · `첨부 업로드` · `리치 텍스트 작성`

**곁들이는 것**
`필터·검색 바` · `요약/합계 패널` · `코멘트·메모 스레드` · `첨부 목록(읽기)` · `단계·진행 표시` · `결정 버튼 묶음` · `빈 상태`

## 4. 어떻게 뽑나

**기계로 셀 것 — 먼저 하고, 그 목록 위에서 사람이 판정하세요.**

```bash
# 화면(라우트) 목록
find . -path ./node_modules -prune -o -name "page.tsx" -print | sort        # Next App Router
# (다른 프레임워크면 라우트 정의 파일에서 뽑으세요)

# 우리 패키지 부품 사용 빈도 — 「무엇이 이미 잘 쓰이나」
grep -rho "<[A-Z][A-Za-z]*" --include="*.tsx" src | sort | uniq -c | sort -rn | head -60

# 자체 컴포넌트 목록 — 「무엇을 직접 만들었나」(= 표 D의 씨앗)
find src -name "*.tsx" -not -path "*/node_modules/*" | grep -iv "page\|layout" | sort

# 막힌 자리
grep -rn "TODO\|HACK\|임시\|우회\|어쩔 수 없" --include="*.tsx" --include="*.ts" src | head -40
```

**사람이 볼 것 — 기계가 못 가리는 셋**

1. **화면 유형** — 코드로는 «이 페이지가 목록형인지»를 못 압니다. 라우트 목록을 훑으며 손으로 태그하세요.
2. **블록 경계** — «여기부터 여기까지가 한 덩어리»는 눈으로 봐야 압니다. 스크린샷을 띄워놓고 세는 게 빠릅니다.
3. **폭·높이 성격** — 12칸 기준 눈대중이면 충분합니다. 정확한 px은 필요 없습니다.

**시간이 없으면 우선순위:** 표 B > 표 D > 표 A > 표 E > 표 C.
표 B 하나만 있어도 저희 쪽 작업이 시작됩니다.

## 5. 답을 받으면 우리가 하는 일

받은 숫자로 이렇게 가릅니다 — **미리 알려드리는 이유는, 그래야 무엇을 세는지가 서로 같아지기 때문입니다.**

| N | 판정 |
|---|---|
| **≥3 화면** | **지금 부품으로 뽑는다** (rule of three) |
| 2 | 보류 — 세 번째가 나오면 그때 |
| 1 | 그 화면의 사정. 부품 아님 |

그리고 표 B의 **폭·높이**가 그대로 그 위젯의 **`footprints`**(= 페이지 격자에서 점유 가능한 칸 조합)가 됩니다. 그래서 눈대중이라도 꼭 적어 주세요 — 이 값이 없으면 «위젯은 만들었는데 몇 칸짜리인지 모르는» 상태가 됩니다.

---

## 6. 주의 셋

1. **«이런 부품이 있으면 좋겠다»는 적지 마세요.** 그건 표 D·E의 *사실*(몇 번 손으로 만들었나 / 무엇을 못 했나)로 적으면 저희가 읽어냅니다. 희망사항은 빈도 데이터를 오염시킵니다.
2. **화면 수가 적은 유형도 반드시 적어 주세요.** N=1도 데이터입니다 — 그게 «아직 안 만든 화면 유형»의 단서일 수 있습니다.
3. **경로를 꼭 붙여 주세요.** 판정이 갈릴 때 저희가 직접 열어 봐야 합니다. 숫자만 있으면 검증이 불가능합니다.
